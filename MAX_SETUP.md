# Запуск той же логики в MAX вместе с VK

`bot.py` остаётся VK-ботом. `max_bot.py` — отдельный webhook-адаптер MAX, который вызывает те же обработчики тестов, результатов и команд. MAX-ID записываются в общие таблицы как отрицательные `user_id`, VK-ID остаются положительными — состояния пользователей не смешиваются и миграция существующих строк не нужна.

## Настройка MAX

1. Создайте и активируйте чат-бота в [MAX для бизнеса](https://business.max.ru/self), пройдите доступную модерацию и получите токен.
2. В Railway оставьте существующий VK worker (`python bot.py`) без изменения.
3. Создайте **второй сервис** из того же репозитория для MAX, задайте Start Command `python max_bot.py` и включите для него публичный HTTPS-домен.
4. В обоих сервисах укажите **один и тот же PostgreSQL `DATABASE_URL`**. Не используйте раздельные локальные SQLite-файлы, иначе у VK и MAX будут разные данные.
5. В MAX-сервис добавьте переменные:
   - `MAX_BOT_TOKEN` — токен MAX-бота;
   - `MAX_WEBHOOK_URL` — публичный HTTPS URL вида `https://<домен-сервиса>/max/webhook` (только порт 443);
   - `MAX_WEBHOOK_SECRET` — случайная строка из 5–256 символов `A-Z`, `a-z`, цифр, `_` и `-`;
   - `MAX_STATS_ADMIN_IDS` — числовые ID администраторов MAX через запятую;
   - `MAX_API_BASE=https://platform-api2.max.ru` (обычно можно оставить значение по умолчанию);
   - при необходимости показа имён VK-пользователей в MAX-выгрузке — секрет `VK_TOKEN` (не добавляйте его в git). Без него MAX-бот продолжит работать, но имена VK-пользователей в его Excel-выгрузке будут пустыми.
6. Если MAX API сообщает об ошибке проверки сертификата, установите доверенный сертификат Минцифры в MAX-сервис и укажите путь в `MAX_CA_BUNDLE`. TLS-проверка в коде не отключается.
7. Разверните MAX-сервис. Он создаёт подписку webhook на `message_created` и `bot_started`; проверьте здоровье по `/health` и отправьте боту «меню».

MAX отправляет webhook на HTTP-сервер MAX-сервиса; VK продолжает работать через свой Long Poll worker. В MAX меню и варианты ответа представлены кнопками MAX, общая анкета и результаты хранятся в общей PostgreSQL. Кнопки MAX отправляют текстовые сообщения, поэтому ответы остаются совместимыми с текущим обработчиком.

## Проверка

- В логах MAX-сервиса должна появиться строка `MAX webhook subscription registered` (либо `MAX webhook subscription already exists`).
- Для ответа на `/stats` администратор MAX должен быть указан в `MAX_STATS_ADMIN_IDS`; VK-администраторы настраиваются отдельно через `STATS_ADMIN_IDS`.
- При проблеме с отправкой смотрите ошибки с префиксом `MAX`, не публикуя токен или webhook-секрет.
